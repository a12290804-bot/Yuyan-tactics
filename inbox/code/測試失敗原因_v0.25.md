# hex 測試 77/86 與 createBattle：原因與建議（給 Claude）

## 結論
程式本身沒有壞。`tests/core_tests.js` 已經是 v0.25 版（11/13 上傳），但它 `require('../core.js')` 和 `../data.js`，讀到的是根目錄 11/12 的舊檔（data.js 標 v0.17：6 層、沒有 rr_ 遺物、個性牌每套 6 張、沒有 reso/story/secretMem、沒有 polStage7）。
把 hex/core.js、hex/data.js、hex/text.js 放在一起跑同一份測試：**86/86 全過**。

9 項失敗（C47、C69、C80–C86）全是 v0.20 以後才有的功能，舊檔沒有，所以才會剛好卡在完全非人、污染、同體宿敵、新章節。

## createBattle
`createBattle` 是舊《永生戰棋》戰棋版的函式。11/12（commit 572eb94）根目錄 core.js 換成卡牌版時就拿掉了。`tests/run_tests.js`（T/S 系列 29 項）是戰棋版的測試，現在 0/29 是預期中的，不是退化。
但 CLAUDE.md 第 2 條還寫「修改前後執行 `node tests/run_tests.js`」，會誤導。

## 建議
1. 選一份當主線：把 hex/ 的 v0.25 三個檔搬回根目錄（或讓測試改 require `../hex/`），不要兩份並存。
2. CLAUDE.md 和 README 的測試指令改成 `node tests/core_tests.js`（README 還寫 73 項）。
3. `tests/run_tests.js` 移到 `tests/legacy/` 或刪掉；若想保留戰棋版，連同舊 core 一起封存。
4. data.js 的 `version` 和實際版號對齊（hex 是 v0.25，根目錄 v0.17）。
5. 加一條最前面的測試：檢查 `D.version` 和 core 的版號一致，以後放錯檔會第一行就紅。
