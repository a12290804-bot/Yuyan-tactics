## 算法

只比「類型＋費用＋效果」完全相同：`t`、`c`、`JSON.stringify(fx)`。不管牌名、角色 `ch`、圖、升級效果 `u.fx`。

沒有 `fx` 的牌不列入（五張詛咒：`x_whisper`、`x_glove`、`x_name`、`x_talisman`、`x_fourth`，效果寫在 `onDraw` / `endHand` / `noRemove`）。v0.25 那份清單用的就是這個算法：2023 張、151 組、463 張。

## v0.11b＋v0.12 複驗（918a6f9、b292bd3）

工作複本：`/workspace/game/dedupe_v012/`。算法不變：有 `fx` 的牌，比類型＋費用＋效果，不管角色。

```js
for (const k in DATA.cardPatch) {
  const c = DATA.cards[k], p = DATA.cardPatch[k];
  if (!c) continue;
  const u = (c.u || p.u) ? Object.assign({}, c.u, p.u) : undefined;
  Object.assign(c, p);
  if (u) c.u = u;
}
Object.assign(DATA.cards, DATA.newCards, DATA.ringCards);
Object.assign(DATA.cards, DATA.guCards); // rules_v0.12_patch.js
```

### 還有的問題

1. **45 張新能力牌還是進不了有本源的牌池。** 拿掉 `deep:1` 不夠。`pool()` 第 220–221 行，語嫣／克勞德只要選了本源，只收有 `bl`（本源）或有 `tag`（個性／慾望／癖好）的牌；沒有這兩欄的，只在語熙且 `ch==='yx'` 時才進。`yy_pw2_*`、`cl_pw2_*` 只有 `ch`，沒有 `bl`、`tag`。用 `C.newRun(..., {origin:'B01'})` 測，30 張語嫣新能力牌全部不在 `pool()` 裡；克勞德選 `paper` 本源同樣 15 張都不在。只有沒選本源時，語嫣那 30 張才會進。現有 hex 裡沒有 `bl`、`tag` 的語嫣牌有 39 張，有本源時同樣 0 張在池裡，這是舊規則，不是這次才壞。要讓玩家抽到這 45 張，得改 `pool()`（建議給這 45 張加 `gen:1`，本源池多一個「`c.gen` 且角色相符」的條件），不要把那 39 張舊牌一次全放進來。

2. **消耗欄位寫成 `x:1`，引擎認的是 `ex:1`。** hex 資料裡消耗都是 `ex:1`（約 14 張），沒有 `x:1`。`yy_r_envy`、`gu_eyeagain` 寫了 `x:1`，打出後不會進消耗堆，牌面也不會寫「消耗」。請改成 `ex:1`。

   - C19 要求每張牌的說明長度 >2。這 13 張的 `fx` 全是引擎還不認識的 op，說明只剩「。」：`yy_r_pride`、`yy_r_obsess`、`yy_r_cruelty`、`yy_r_wrath`、`yy_r_sweetmalice`、`yy_r_glutton`、`gu_last3`、`gu_samesys`、`gu_cross`、`gu_bypage`、`gu_calib`、`gu_predict`、`gu_eyeagain`。要先在 `opText`（core.js 第 84–167 行）補這些 op，C19 才會過。

## 第一次 v0.11 的合併方式（已過時，見上方複驗）

照 patch 檔頭：

```js
for (const k in DATA.cardPatch) Object.assign(DATA.cards[k], DATA.cardPatch[k]);

```

假設：

- 用淺層 `Object.assign` 覆寫既有欄位，id、牌名、圖、`ch`、`r`、`tag`、`bl` 沒寫進 patch 的都保留。

### 2. 45 張新能力牌進不了牌池

`yy_pw2_01`～`yy_pw2_30`、`cl_pw2_01`～`cl_pw2_15` 全部帶 `deep:1`，但沒有 `tag` 也沒有 `bl`。`pool()`（core.js 第 220–221 行）遇到 `c.deep` 會檢查 `st.deepOk` 有沒有 `c.tag||c.bl`，這兩欄是空的，條件永遠不成立。這 45 張不會出現在獎勵、商店、草稿裡。

另外名稱都是「（待命名）」、圖都是 `TBD`，等文字劇情大師和製圖大師補。能力鍵都找得到，沒有缺 `DATA.powers` 的。

### 3. 第六節戒指改動不在這個 patch 裡

規則文件第六節改了貪、虛、妒、饞、獻，並新增 `vain`、`eatX2`、`lastStand`。`cards_v0.11_patch.js` 裡沒有 `yy_r_*`，也沒有這三個新 op。hex 資料裡也還沒有十指戒牌（只有舊的慾望牌 `yy_pride`、`yy_greed`）。這三個效果引擎現在不認識；`desc()` 對不認識的 op 是回空字串、不會丟錯，所以「用 core.desc 跑過 0 錯誤」驗不到這件事。

### 4. 其他檢查

- patch 248 筆全部對得到現有 id，沒有指向不存在的牌。
- 合併後的 `fx` / `u.fx` 沒有引擎不認識的 op。`vain` / `eatX2` / `lastStand` 只寫在規則文件裡，不在資料檔。
- 詛咒本來就沒有 `fx`，不是這次搞壞的。
- 每個個性標籤仍是 8 張；帶 `deep` 的標籤牌沒有撞效果。hex 測試 C84 會過。
- 顧沉舟還是 4 張：`gu_shot`、`gu_note`、`gu_pull`、`gu_leak`。規則寫下一版補到 15 張，這版沒補。
- 合併後的 hex 測試（工作複本，86 項）全過：86／86。底層數值、大招、新 op 還不在這份 patch 裡，測試沒覆蓋到那些。
